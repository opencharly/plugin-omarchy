## Summary

Convert the 17-word `#OmarchyInput.method` catalog in
`candy/plugin-omarchy/schema/omarchy.cue` to the §10.1 S3 vocabulary-table idiom, so the
closed set of words has ONE home and the enum an author meets is `or()` of that table's
word list:

```
_method          (+ _methodWord)
```

That is the 6 `union` rows `design/dpat-baseline.tsv` records for this file — **ONE
disjunction, not 6:** the catalog is written one alternative per line, so five of the
six rows carry a trailing `|` and the 17th word, `version`, closes the disjunction and
carries none. A union's row count is a property of its formatting, so the row number is
the only honest way to compare repos and it is not a count of disjunctions. Every row
this repo carried is retired by this PR; no row is left to judgement.

**The one judgement call, and how it is preserved.** `method` carries a literal default,
`*"cli"`. S3 permits a literal default inline (`scripts/design-dpat.sh`'s
`literal_default`: a single bare `|` with a `*"…"` on one side is not a union), and the
default is a VALUE choice the word table does not carry — so it stays written out, in
the S3 form the gate permits:

```cue
method: *"cli" | or(_methodWord)
```

The alternative I considered and rejected — putting the default inside the table — would
make the table's rows mean something they do not (which words exist, not which word
applies when none is given), and would move the default out of the one line that states
it. The accepted set is IDENTICAL before and after: 17 method words and the same default
`cli`, read from the compiled CUE on both sides (179-case differential, §4). The default
is also the verb's own zero-value arm, and one test pins those two together.

The generated Go does not move either: `Method string` is byte-identical, and the only
line the regeneration changes is that field's doc comment (the S3 statement).
